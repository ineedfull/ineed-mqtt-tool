# Release Packaging Design

## Goal

Make Electron release output predictable and easy to transfer. Every packaging run starts from an empty `release` directory and finishes with distributable ZIP archives only.

## Scope

- Apply cleanup only to Electron packaging commands, not to the regular Vite `npm run build` command.
- Keep the existing Electron Builder platform targets.
- Wrap Windows portable executables and Linux AppImage files in ZIP archives.
- Keep macOS ZIP archives as generated by Electron Builder.

## Final Output

The `release` directory may contain only platform ZIP archives after a successful packaging run. Every ZIP filename includes the shared local build timestamp in `yyyyMMdd-HHmmss` format. It must not retain:

- `mac`, `mac-arm64`, `win-unpacked`, `win-ia32-unpacked`, or `linux-unpacked` directories
- `.blockmap` files
- raw `.exe` or `.AppImage` files
- Electron Builder diagnostic YAML files

## Components

A small dependency-free Node script owns release preparation and finalization:

- `clean`: removes and recreates `release` before Electron Builder starts.
- `finalize`: creates ZIP archives for raw Windows and Linux outputs, then removes raw files and intermediate artifacts.

Package scripts compose these operations around Electron Builder. The helper exposes testable functions so filesystem behavior can be verified without running a full platform build.

## Failure Behavior

- Packaging stops immediately when cleanup, Electron Builder, or finalization fails.
- Finalization validates that expected raw artifacts exist before deleting them.
- A failed finalization does not report success; any remaining files are kept for diagnosis until the next packaging run clears them.

## Verification

- Unit tests create a temporary release tree and verify clean/finalize behavior.
- Existing tests and lint must remain green.
- A packaging smoke test verifies that the real `release` directory contains ZIP files only.
