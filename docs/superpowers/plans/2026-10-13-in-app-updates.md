# MQTT 应用内更新实施计划

> 按用户要求在当前源码目录串行实施，不使用子代理或复制源码。采用 superpowers:executing-plans 和 test-driven-development。

**Goal:** 两端实现应用内下载、校验和用户确认后的重启安装，完成隔离测试；缺少签名材料时拒绝正式发布。

**Architecture:** Vue 共用更新状态界面。Electron 使用 electron-updater 6.6.2 并验证签名元数据；Tauri 使用官方 updater 插件。原生端控制可信版本、下载缓存与安装入口，严格保存握手先于安装。

**Spec:** `docs/superpowers/specs/2026-10-13-in-app-updates-design.md`。用户确认先完成实现和隔离测试，暂缺签名材料。

## 约束

- 固定应用身份、SQLite 结构与用户目录；所有测试使用隔离目录。
- 生产 HTTPS 与更新签名不可绕过，正式制品缺少签名明确失败。
- 旧检查 JSON 保留；原生 feed 与新增制品独立验证，不破坏三工具公共发布脚本。
- 不上传、不公开测试版本；配置平台不等于原生安装升级验收。

## 执行清单

- [x] Electron 控制器：`electron/updateController.cjs` 与 `tests/updateController.test.js`。先以真实临时文件与 Ed25519 签名写测试，运行缺模块失败；实现签名/渠道/摘要/状态/并发/保存拒绝，复跑通过。
- [x] Tauri 控制器：新增 `native_update.rs`，注册官方插件、原生状态和限定命令。先写签名失败与安装状态门禁测试，再实现检查、分开下载安装、进度与保存握手，运行 Rust 更新专项。
- [x] 共享协议/界面：扩展 contract、facade、preload 和两个 adapter；新增共享更新面板和严格更新准备。先写组件进度/失败/重开恢复回归，再实现；运行 adapter、preload、组件与 lint/构建。
- [x] 发布工具：新增 MQTT 专用签名/生成更新 feed 入口，维持原人工安装入口。先验证缺签名/篡改/错误渠道拒绝，再实现；验证真实文件与生成元数据摘要，运行原发布回归。
- [x] 隔离验收：下载真实分块与损坏测试、生产缺签名拒绝、双端控制器原生 API 与 UI 回归；更新产品文档及工作区任务，逐项说明尚未通过的真实安装升级与公网条件。

每项先红后绿；业务验证与原生安装器替身分开记录。不把替身的 install 调用当作真实安装完成。
